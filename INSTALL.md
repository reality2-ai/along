# Install Along and use it offline

**Use at your own risk.** Along is an experimental AI-coding course app, not an
official Auckland Transport service. Check important journey and accessibility
information with AT.

These instructions describe Along version 38. Check the version in Settings.
Along Device Preview is a separate installation; its saved places and device
keys are not imported automatically. Do not clear website data to update: that
can erase saved places and device keys.

## Prepare and install

Open Along in the browser you intend to use for installation. Wait until the
timetable and addresses are ready offline, then follow your platform's steps
below. Open the installed app and try a new address search in flight mode.
The web portal provides downloads and updates; it does not calculate journeys.
Downloaded address search and scheduled planning run on your device.

## Choose your browser and platform

| Platform | Installation paths covered here |
| --- | --- |
| Windows | Chrome, Edge, Brave |
| Linux | Chrome, Edge, Brave; desktop integration varies by distribution |
| macOS | Chrome, Edge, Brave; Safari on macOS Sonoma 14 or later |
| Android phone/tablet | Chrome; Edge or Brave when their install/home-screen action is available |
| iPhone/iPad | Safari; Chrome's Share action; Edge/Brave through Share if offered, otherwise use Safari |
| Chromebook | Chrome |

Safari is not a current installation option for Windows, Linux or Android. Menu
names vary with browser versions. These are instructions, not a claim of physical
validation of every combination. After installing, always reopen online, check
Settings → offline ready, then test a new journey with the connection disabled.

## Chrome — Windows, Linux, macOS and Chromebook

1. Open Along in Chrome and finish preparation.
2. Select the install icon in the address bar, or **⋮ → Cast, save and share →
   Install page as app**. Confirm the installation.
3. Open Along from Start on Windows, your application launcher on Linux, your
   app launcher/Spotlight on macOS, or the Chromebook Launcher. You can also find
   installed apps at `chrome://apps`.
4. Pin the app to your taskbar, Dock or shelf using your operating system's menu.

[Google's desktop instructions](https://support.google.com/chrome/answer/9658361?hl=en&co=GENIE.Platform%3DDesktop).

## Edge — Windows, Linux and macOS

1. Open Along in Edge and finish preparation.
2. Select the install icon, or **… → More tools → Apps → Install this site as an
   app**. Some versions put **Apps** directly in the menu. Confirm.
3. Open `edge://apps` to find Along. On Windows, its Details page offers Start,
   taskbar and desktop shortcuts. On Linux/macOS, use the system's application
   launcher and pin the running app if wanted; the available shortcuts vary.

[Microsoft's installation and app-management instructions](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge).

## Brave — Windows, Linux and macOS

1. Open Along in Brave and finish preparation.
2. Select the install icon if shown, or use the main menu's **Save and Share →
   Install page as app**. Some versions use **Cast, save and share**. Confirm.
3. Open Along from your operating system's application launcher, then pin it
   there if wanted. Keep Brave and the profile used for installation available.

Brave's [support-team explanation](https://community.brave.com/t/progressive-web-applications-pwa-in-brave/605917)
describes the desktop menu. Along's **Install Along** button in Settings is another
entry point when the browser offers it. If no installation action is available,
use a current supported browser; creating a bookmark alone does not prove offline
preparation. Brave-specific physical validation is pending.

## Safari — macOS

On macOS Sonoma 14 or later, open Along in Safari, then choose **File → Add to
Dock** (also available through Share). Name it Along, choose Add, and open the
new app from the Dock or Spotlight. Check offline readiness inside that app while
still online; it can have separate storage from Safari. On older macOS versions,
use a maintained Chrome, Edge or Brave version with web-app installation.
[Apple's Mac instructions](https://support.apple.com/en-ie/104996).

## Chrome — Android phone or tablet

Open Along, finish preparation, then tap **⋮ → Install and create shortcut →
Install**. Depending on the version, the menu may instead show **Install app** or
**Add to Home screen**. Confirm and open the new Along icon from the home screen
or app launcher. Settings → **Install Along** may also be available.
[Google's Android instructions](https://support.google.com/chrome/answer/9658361?hl=en&co=GENIE.Platform%3DAndroid).

## Edge or Brave — Android phone or tablet

Open Along and finish preparation. First try **Install Along** in the app's
Settings, if shown. Otherwise open the browser menu and look for **Install app**,
**Add to Home screen**, or **Add to phone**. Choose the available action and confirm
placement of the icon. Open that icon online, then repeat the offline check.

The label and whether you get a standalone app or a home-screen shortcut depend
on the browser/version. We have not verified every mobile menu. If no installation
action is offered, open the same Along URL in Chrome and use its documented path;
that browser/profile will need its own download. Do not confuse adding a favourite
with preparing an offline app. [Brave's Android project](https://github.com/brave/brave-browser/issues/25121)
tracks home-screen installation UI; [Microsoft's mobile help](https://support.microsoft.com/en-us/microsoft-edge/microsoft-edge-for-mobile-faqs-29296eab-b76f-4a87-ac9c-9835da53465d)
covers Edge's mobile browser, whose menus differ from desktop.

## Safari — iPhone and iPad

Open Along in Safari, then choose **Share → Add to Home Screen**. Use **View More**
or **Edit Actions** if needed. Enable **Open as Web App** if offered, then tap
**Add**. Open the new icon while online and wait for offline readiness inside it.
Physical iOS/iPadOS validation of Along is pending.
[Apple's iPhone instructions](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios),
[Apple's iPad instructions](https://support.apple.com/guide/ipad/open-as-web-app-ipad8f1f7a29/ipados).

## Chrome — iPhone and iPad

Open Along in Chrome. Use **Share → Add to Home Screen**, confirm the name and tap
**Add**. Open the icon online before testing offline. If the option is absent,
open the address in Safari and follow the Safari steps. Google notes that a
home-screen item can open either a web app or the default browser depending on
availability: check the actual result rather than assuming the icon is sufficient.
[Google's iPhone/iPad instructions](https://support.google.com/chrome/answer/9658361?hl=en&co=GENIE.Platform%3DiOS).

## Edge or Brave — iPhone and iPad

Open the browser's Share action and use **Add to Home Screen** if offered. If it
is missing, copy the Along address into Safari and use **Share → Add to Home
Screen** there. Do not use desktop instructions such as **Install page as app** on
iOS. Brave's support team documented iOS limitations separately from its desktop
support; this guide does not assume a later mobile version has the same menu.
Finish preparation in the installed icon and perform the offline check.
[Brave's support response](https://community.brave.com/t/progressive-web-applications-pwa-in-brave/605917),
[Apple's installation path](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

## If installation is unavailable

You can use Along in a supported browser tab and bookmark its HTTPS address.
Offline use still depends on successful app/data caching in that browser profile.
A saved HTML page, screenshot, ordinary shortcut or unpacked `file://` ZIP is not
an offline installation. Browser menus change; follow the official instructions
for the browser/version you use. The platform list describes installation paths,
not a claim that every platform has been physically tested.



## Scheduled journeys, optional current information

By default, departures and journey times come from the downloaded timetable.
They do not show where a bus or train is now, and may not reflect delays,
cancellations or changed services. Along labels current information separately
when it can obtain and match it. An unavailable or unmatched live result leaves
the schedule in place; it does not mean the service is on time.

To choose live information, open **Settings → Device and AT-key setup**. Create
your device group, then choose **Use my own AT key** and **Set up live information**.
You need your own Auckland Transport API subscription key. Browser requests go
directly to AT; AT receives your IP address and the key. There is no Along live-data
proxy. The key is stored encrypted in this browser's device setup. Clearing site
data can remove access. The offline planner does not require a key.

Current information is requested for the stop, journey or route you are viewing.
It is not a background location tracker. Use the official AT app or website when
you need information that Along cannot verify.

## Keep your data on your devices

Search history and current location stay on your device. Saved places and service
preferences are shared only when you connect your devices and permit journey
sharing. Device pairing and permission to share are separate steps. No Along
server stores your journeys. Feedback sent to GitHub is public: review the draft
before choosing to send it.

Device keys use encrypted browser software storage. This is a limited R2 subset,
not hardware-backed protection or protection from a compromised browser or scripts
on the same website. Keep backups you control; browser storage can be removed by
the browser, operating system or a person clearing site data. A removed device
may retain previously received data. Revocation takes effect when another device
learns the signed update. Replace a compromised AT key through AT itself.

## Optional automatic connection

After pairing and permitting journey sharing, open **Settings → Share saved
journeys with my devices → Automatic connection with a relay**. Enter your chosen
compatible secure `wss://` R2 relay on each device. No relay is selected by default.
The actual R2 implementation has passed local tests; external endpoint and mobile
network compatibility remain to be checked.

Keep both apps open. A relay connection alone is not proof that the other device
received your saved places; look for its saving confirmation. Offline edits stay
local until reconnection. Mobile browsers can suspend background apps. Recovery
choices and devices at different checkpoints may need an explicit review before
sharing continues. Initial pairing still requires exchanging connection messages.

**Stop automatic relay sharing** keeps the address for later; **Remove relay
address** clears that choice. Both preserve saved places. A relay sees your network
address, device/group identifiers, certificates, traffic timing and message sizes.
Journey payloads are encrypted between permitted devices. This relay connection
does not send your AT key, learning history or current location. Planning and
direct AT requests work independently of the relay.

## Update and reopen

Use **Settings → Check for an app update** or the app's `update.html` page in the
same browser used to install it. Choose **Update and reopen**, then reopen the
installed app and check its version. Pulling down to refresh also checks for an
update; offline checks stay quiet. Saved places and downloaded travel data should
remain. If an update fails, keep the existing app and retry online.

**Forget history and saved places** clears those local choices. When journey
sharing is enabled, saved-place removals are also shared with permitted devices
when connected. This is different from removing a relay address.
